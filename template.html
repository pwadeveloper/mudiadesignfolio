A course platform built with AI agents, and a record of every way it broke. KayKav Academy needed its own place to sell and teach courses to designers in Nigeria and Europe: paid video lessons, quizzes, certificates and local payments.

From 18 July to 14 October 2026 I designed the product and directed its build with Claude Code, one verified step at a time, across 203 commits. Every decision and failure went into a running log called STATUS.md. This is what that log taught me.

/01

The Brief

A calm reading room that happens to have excellent video

KayKav Academy is my school for creatives, with courses like Built, Not Prompted, which teaches non-developers to ship working software with AI tools. I had been running it as live cohorts. To sell courses on their own I needed a platform that took payment in naira, kept paid video behind a real lock, and gave students a certificate that meant they had done the work.

Off-the-shelf course tools fell short on two counts. Most can't take local payments well, and most treat a course as a video playlist. I wanted the reverse. The reference points were Domestika for craft video and the Interaction Design Foundation for structured, text-heavy rigour.

The platform must feel like a calm reading environment that happens to have excellent video.PRD §1, the core tension

Before any code, I wrote the product requirements, eight feature specs and ten golden rules every line had to obey. Money is stored as whole kobo and cents, never decimals. Access is only ever granted by the payment provider's confirmation. Servers sit in Frankfurt, the latency midpoint between Lagos and Europe, while Cloudflare's edge serves the heavy video from close to each student.

/02

The Method

One verified step at a time, with a continuity log

I don't write production code by hand. I design, specify and direct, and an AI agent writes the code. The risk with that setup is drift: step ten quietly builds on something the agent invented in step three. So I broke the build into a Prompt Pack of 24 steps, each with the same four parts.

  • Context. What's true now, and which spec governs this step.
  • Build. Exactly what to produce.
  • Verify. A command or test that proves it worked. If it fails, the next step doesn't start.
  • Handoff. What the next step needs to know, written into STATUS.md in the same commit.

STATUS.md works like a script supervisor's continuity notes on a film set. Every take is logged, so whoever shoots tomorrow can match what was shot today. Any session, human or agent, starts by reading it, and each incident becomes a standing rule in the agent's instructions file, CLAUDE.md.

/03

Decisions

Four problems with only one right answer

Some choices look like matters of taste and aren't. I worked these out in the specs before building, wrote the reasoning down, and told the agent to implement them exactly. Each exists because the obvious approach quietly fails.

  • Progress is earned on the clock. A certificate needs 90% of each video watched. The platform keeps two numbers, where you are and how much you've actually watched, and only real playback capped by the server's own clock adds to the second.Like a taxi meter: it charges for the minutes the ride took, whatever the passenger says.
  • Only the payment provider grants access. A "payment successful" redirect is a claim from the browser. Access waits for Paystack's signed webhook, and the handler is safe to receive twice.Like waiting for the bank alert before releasing goods, instead of trusting a screenshot of a transfer.
  • Quiz answers never leave the server. The correct option sits in a column students' requests can't read, and a test scans what actually crosses the wire.Like printing the exam paper without the answer key stapled to the back.
  • Access rules guard rows, not values. They decide whose record you can touch, not what you write into it. Progress and payment state are written only by trusted database functions.Like a hotel key card: it opens your room, and does nothing to stop you rewriting your own minibar bill.

/04

Design

Two looks, one set of roles

Components are named by the job they do, like surface, ink and action, never by a colour. That let the product offer two looks from one set of parts: the marketing site's brand-blue canvas, or blue chrome around white reading surfaces for long sessions. Gold is reserved for the one action on each screen, with a black label. Body text is set at 17px with generous line spacing, because most of a lesson is reading.

The video player was rebuilt with 44px gold control tiles and a quality menu, and it resumes where you stopped. The lesson outline breaks out of the centred grid to sit 32px from the window edge, so the reading column stays exactly 720px wide at every screen size.

  • Learning. Scrub-proof video progress, quizzes with rate-limited retakes, signed PDF certificates, search.
  • Buying. Paystack checkout and webhook, guest checkout, receipts, bank transfer with an audit trail, discount codes.
  • Running it. Course editor with autosave, direct-to-Cloudflare uploads, invites with bulk CSV enrolment, terms approved by counsel.

/06

What I Keep

Six rules the log earned

Most incidents shared one shape: a check that existed somewhere my gates didn't look. The fixes that held were tests that go and ask, written against the whole folder or schema instead of the one file someone already suspected.

  • A comment is not a gate. A note saying "remember to add this" is only read by someone already in the file they forgot to open.From the admin navigation bug, twice
  • Passing tests don't mean it compiles. 916 tests passed over a file that didn't compile. Types, lint and tests are three separate checks, run last.From 14.08.26
  • Test with the data the rules hide. A hidden row comes back as an empty result with no error. Only a draft or someone else's record can catch it.From the same silent bug in three features
  • Ship a refusal with its caller. Additive database changes can go first. Anything that refuses, constrains or revokes ships with the code that expects it.From the quiz crash
  • Name the database before you trust it. Dev and production came to share a hostname, so every script prints the project's unique reference.From a dev scan briefly read as production
  • Measure the rendered page. Component tests load no CSS. Look at the page at 1280 and 390, and measure what's inside each box.From the pasted-link overflow

/07

Outcome

Live, selling, and still being logged

The platform runs at learn.kaykav.academy and hosts the academy's courses, including Built, Not Prompted, the Druids Alpha Masterclass and Building a Better Creative Business. Students pay in naira through Paystack or by bank transfer, enrol by invite, take quizzes and download certificates. The terms and privacy policy were approved by counsel and are published from the same repository the app runs on.

The bigger result for me is the method. A designer can direct an agent to build software that handles real money, as long as the work is broken into steps that prove themselves and every failure becomes a rule the next step has to read. That is what I now teach in Built, Not Prompted.

If I started again, I'd write the guard tests for framework rules on day one, classify migrations from the first file, and keep every credential out of the chat from the first session.

Before

  • Courses taught as live cohorts only
  • Test suite: 194 seconds, and flaky
  • Lessons learned kept in people's heads

After

  • Self-paced courses on our own platform, live since August 2026
  • Test suite: about 11 seconds, same result every time
  • Rules written into CLAUDE.md and enforced by tests
